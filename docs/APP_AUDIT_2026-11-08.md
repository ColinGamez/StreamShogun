# App audit: November 8, 2026

## Fixed in this pass

- Billing checkout checks Stripe for an ongoing subscription before creating another checkout.
- Checkout completion verifies the subscription with Stripe before granting Pro. Failed webhook processing returns an error so Stripe can retry.
- Website checkout displays service errors instead of treating every failure as a missing login, and blocks repeated clicks while a request is pending.
- Annual billing selection survives login, registration, and expired sessions. The account page shows the annual price before the user starts checkout.
- Browser playlists record channel ownership, deduplicate imported URLs, and remove channels without removing URLs shared with other playlists.
- Desktop startup clears stale channel state when the database is empty. Failed playlist or guide deletions preserve the UI entry and display an error.
- Website authentication and checkout regression tests run with the normal test command.
- Dependency security updates raise fast-jwt, js-yaml, and shell-quote override floors and migrate the API/shared schemas to patched Zod 4. Record schemas declare their key types explicitly, and validation middleware uses the supported issue list.

## Remaining work

- Dependency audits still report noncritical findings. Production: 7 moderate and 5 low. Including development tooling: 41 high, 38 moderate, and 15 low. Both graphs have zero critical findings; production has zero high findings. The repository's CI thresholds are high for production and critical for the full graph.
- Multiple checkout sessions opened simultaneously in different tabs can still race before either becomes a subscription. Add customer-level session reuse or another atomic guard.
- Browser EPG sources need programme ownership tracking. Removing one of several sources can leave stale programmes; overlapping sources also need a defined restoration policy.
- Legacy browser playlist entries lack channel ownership metadata. Their channels are retained conservatively while legacy entries remain and clear when the last playlist is removed.

## Release boundaries

Website changes are published through the Git-linked Vercel production deployment and checked against the public files at streamshogun.com. The API is hosted separately on Render; a healthy endpoint alone does not prove a particular source revision is deployed. Desktop source fixes require a newly built installer release to reach existing users. No real payment or subscription was created during verification.

## Validation

All 689 tests pass: 16 website, 99 core, 180 UI, 70 desktop, and 324 API. Workspace type checking, lint, formatting, the full production build, and frozen-lockfile installation pass. Security updates meet both configured CI audit thresholds; the counts above record the remaining findings rather than suppressing them.
